# Deploying for free

The whole app runs as **one Docker container**: Django serves the API, the
admin and the built React app. Because everything is on one origin, the
httpOnly refresh-token cookie stays first-party and no CORS setup is needed.

| Piece | Service | Free tier (verify current terms before you rely on it) |
|---|---|---|
| App (Docker) | [Render](https://render.com) web service | 512 MB RAM. **Sleeps after 15 min idle**, and the first request after that takes ~1 min. 750 instance-hours per month, enough for one service running all month |
| Database | [Neon](https://neon.com) Postgres | 1 GB storage per project. Compute pauses when idle and wakes in about a second. **Does not expire**, unlike Render's free Postgres, which is deleted after 30 days |
| Product images | Any S3-compatible bucket | Optional, but without one, uploads are lost on every restart (Render's free disk is temporary) |
| Domain | `bazario.onrender.com` by default | Or a free subdomain; see below |

> Free tiers change often. Check each provider's pricing page when you sign up.

---

## 1. Database: Neon

1. Sign up at neon.com and create a project (pick the region closest to your Render region).
2. Copy the **connection string**. It looks like
   `postgresql://user:password@ep-xxx.region.aws.neon.tech/neondb?sslmode=require`.
   You'll paste it as `DATABASE_URL`.

## 2. Image storage (optional, recommended)

Pick any S3-compatible provider with a free allowance, for example
Cloudflare R2, Backblaze B2 or Supabase Storage. Create a bucket and an
access key, then note:

| Env var | Example |
|---|---|
| `AWS_STORAGE_BUCKET_NAME` | `bazario-media` |
| `AWS_S3_ENDPOINT_URL` | the provider's S3 endpoint, e.g. `https://<account>.r2.cloudflarestorage.com` |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | the access key pair |
| `AWS_S3_CUSTOM_DOMAIN` | *optional*. The bucket's public host (e.g. `pub-xxxx.r2.dev`). Set it if the bucket is public; leave it empty to use signed URLs |

Skip this step for a quick demo. Everything works, but uploaded images
disappear when the free instance restarts.

## 3. App: Render

1. Push this repo to GitHub (the Blueprint deploys the `main` branch; change
   `branch:` in `render.yaml` to deploy another one).
2. On render.com: **New → Blueprint**, then pick the repo. Render reads `render.yaml`.
3. Fill in the values it asks for:
   - `DATABASE_URL`: the Neon string from step 1
   - `DJANGO_SUPERUSER_USERNAME` / `_EMAIL` / `_PASSWORD`: your first admin
     account, created automatically on boot (free instances have no shell)
   - the `AWS_*` values from step 2, or leave them empty
4. Deploy. The first build takes a few minutes. When it's done, open
   `https://<service>.onrender.com`. `/admin/` is the Django admin and
   `/api/docs/` is the API reference.

`DJANGO_SECRET_KEY` is generated by Render. Migrations run on every boot.
The service's own `*.onrender.com` hostname is trusted automatically.

### Avoiding the cold start (optional)

A free uptime monitor (e.g. UptimeRobot, cron-job.org) that requests
`https://<service>.onrender.com/api/health/` every 10 minutes keeps the
instance awake. One service running all month stays within the 750-hour
allowance.

## 4. Free domain (optional)

`*.onrender.com` works with HTTPS and needs no setup. For a nicer name:

- **is-a.dev**: free `yourname.is-a.dev` subdomains for developer and
  portfolio projects. You request one with a pull request to their GitHub repo.
- **DigitalPlat FreeDomain**: free names under shared domains such as
  `.dpdns.org` / `.us.kg`. Renewal is manual.
- **GitHub Student Developer Pack**: if you're a student, it includes a free
  real domain (e.g. `.me` / `.tech`) for a year.

Then:

1. In Render: **Settings → Custom Domains → Add** `bazario.yourname.is-a.dev`.
   Render shows the DNS record to create (usually a `CNAME` to
   `<service>.onrender.com`) and issues the HTTPS certificate itself.
2. Create that record wherever the domain's DNS lives.
3. Add the domain to the service's env vars and redeploy:
   - `DJANGO_ALLOWED_HOSTS` = `localhost,bazario.yourname.is-a.dev`
   - `DJANGO_CSRF_TRUSTED_ORIGINS` = `https://bazario.yourname.is-a.dev`

## Running the production image locally

```bash
docker build -t bazario .
docker run --rm -p 8000:8000 \
  -e DJANGO_SECRET_KEY=change-me-to-a-long-random-string \
  -e DATABASE_URL=sqlite:////tmp/db.sqlite3 \
  -e DJANGO_SECURE_SSL_REDIRECT=false \
  -e JWT_REFRESH_COOKIE_SECURE=false \
  bazario
```

Over plain `http://` some browsers drop `Secure` cookies, which is why the
cookie flag is relaxed here. Never do this on the real deployment.
